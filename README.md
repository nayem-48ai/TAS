**A free, open-source agent skill that does speech in BOTH directions — hence
the name TAS (Text And Speech).** Text → natural speech (40+ languages, 100+
voices, custom voice UIDs, long-text chunking, multi-speaker dialogue,
subtitles, caching) **and** audio → text (transcription with word timestamps,
SRT/WebVTT subtitles, long-recording chunking). One script, Python stdlib only —
**no whisper, no torch, no pip install, no model download.** A **mandatory
audio QA loop** verifies every file before delivery.

> Most TTS wrappers stop at "the file exists." This skill decodes the audio,
> measures loudness and true peak, detects silence, and refuses to ship a
> failed file. The verification loop is the difference between a demo and a
> dependable feature.

> **Independent project.** This is an unofficial client for the free
> [TNxBD Studio](https://speakee.tnxbd.top) API (Sonic models). It is
> not affiliated with TNxBD Studio. The API is third-party, free, and has no
> SLA — it may change, rate-limit, or disappear.

## What this is

A self-contained skill folder:

```
skills/tas/
├── SKILL.md                 # agent contract: rules, workflow, commands
├── scripts/tas.py           # the CLI (stdlib only, ~1,200 lines)
├── references/
│   ├── api.md               # endpoints, retries, cache, QA thresholds
│   ├── voices.md            # language/voice catalog, UID mode, presets
│   └── troubleshooting.md   # symptoms and fixes
└── assets/presets.json      # curated voice presets
```

The repo also ships examples, a self-test, and a packaging script.

## Why use it

| Without this skill | With this skill |
|---|---|
| Ad-hoc curl snippets | One CLI with 10 commands |
| Ship silent/clipped files | Machine-checked QA before delivery |
| Long text fails silently | Sentence-aware chunking + merge |
| Guessed voice names | Live catalog + fuzzy resolution + presets |
| Re-synthesize everything | Content-addressed cache and resume |
| Mixed loudness in dialogue | `--loudnorm` to −16 LUFS |
| No subtitles | `--srt` from dialogue timing |
| Human-only output | `--json`, documented exit codes |

## Features

- **40+ languages**, **100+ voices**, 4 models (`sonic-3.5` default).
- **Single voice, custom UID, or multi-speaker dialogue.**
- **Long-text chunking** at sentence boundaries (`।`, `.`, `!`, `?`, `…`).
- **Parallel synthesis** with retries, jitter, and `Retry-After` support.
- **Strict response validation** (audio content type + MP3 header).
- **Cache + resume** in `~/.cache/speakee-tas`; `--force`, `--no-cache`,
  `cache-clear`.
- **Audio QA**: decode, duration, integrated loudness (ebur128), true peak,
  leading/trailing/internal silence.
- **Dialogue tools**: `--map`, `--silence`, `--loudnorm`, `--manifest`,
  `--srt`, `--no-stitch`.
- **Inline emotions**: `[happy]`, `[sad]`, … tags and emoji switch emotion
  mid-passage (per sentence), auto-split and merged; `--no-emotion` to disable.
- **Text cleanup**: strips markdown, HTML, URLs, and emoji (`--raw` to keep).
- **Presets**: `news`, `story`, `assistant`, `audiobook`.
- **Automation**: `--dry-run`, `--json`, distinct exit codes.
- **Speech-to-text** (`stt` / `transcribe` / `subtitle`): transcribe an audio or
  video file, split long recordings into ~120 s chunks, export SRT or WebVTT,
  and estimate word timestamps. Zero ffmpeg needed beyond optional conversion;
  caching is in-memory per run.
- **Zero Python dependencies**; ffmpeg optional (needed for stitching).

## Speech-to-text

Transcribe an audio or video file (`demo.mp3`, `demo-bn.mp3`,
`Conversation_Audio.mp3`) into text with SRT / WebVTT subtitles. Long files
are split near `--chunk-seconds` into silences-aware 120 s segments and
transcribed in parallel; each segment is re-encoded to 16 kHz mono 64 kbps MP3
so uploads stay well under the ~4.5 MB API cap. Word timestamps are optional
(SRT timing falls back to per-character estimates when disabled). Language is
auto-detected from the first chunk, then reused; pass `-l <code>` if the result
looks wrong (auto-detection can be unreliable on short clips).

```bash
S=~/.config/opencode/skills/tas/scripts/tas.py

# Transcribe and write an SRT next to the input
python3 "$S" subtitle demo.mp3 -l en --srt demo.srt

# Transcribe to text + SRT + VTT (machine-readable)
python3 "$S" stt demo.mp3 --json \
  --srt demo.srt --vtt demo.vtt -o demo_transcript.txt

# Estimate word timestamps faster, with smaller chunks
python3 "$S" transcribe demo.mp3 -l bn --no-word-timestamps \
  --chunk-seconds 60 -o bn_transcript.srt

# Plan without real requests
python3 "$S" stt demo.mp3 --dry-run
```

**Limitations:** the underlying model is Whisper-based; automatic language
detection may disagree with your file on short clips, so **always pass
`-l <code>` when you know the language** (use `-l bn` for Bengali — auto-detect
confuses Bengali and Gujarati). **Never install Whisper** — the bundled script
does STT entirely through the Speakee API with the Python standard library.

## Usage

```bash
S=~/.config/opencode/skills/tas/scripts/tas.py

# Single voice (language auto-detected)
python3 "$S" tts "Hey? কেমন আছো তোমরা সবাই?" -o out.mp3

# Long markdown article, preset voice, auto-chunked
python3 "$S" tts --text-file article.md -l en --preset news -o article.mp3

# Inline emotions: tags persist until the next tag; an emoji colours its
# sentence. The text is split per emotion, synthesized, and merged.
python3 "$S" tts "Hey! How are you? [Sad] I heard about your father. 😢" -l en -o emo.mp3

# Dialogue: human + AI must use DIFFERENT voices; a narrator/commenter line
# (no "Speaker:" prefix) gets a 3rd voice via the special key `narrator`.
python3 "$S" conversation dialog.txt -l bn \
  --map "narrator=News Reader,মানুষ=Nayem,AI=Pooja - Everyday Assistant" \
  --loudnorm --srt dialog.srt --manifest dialog.json \
  -o dialog.mp3

# Custom cloned voice
python3 "$S" uid "Text in my voice" -v <voice-uuid> -o cloned.mp3

# Verify any audio file
python3 "$S" verify out.mp3

# Plan without spending requests
python3 "$S" conversation dialog.txt -l bn --dry-run --json

# Discover voices and presets
python3 "$S" languages
python3 "$S" suggest -l en
python3 "$S" presets
```

## Verification (the QA loop)

`tts` and `conversation` run QA automatically after writing the file:

```
QA: PASS | -18.9 LUFS | peak -4.2 dBFS | silence 0.0/0.0/0.0s
FINAL: dialog.mp3 (5 segments, 5 chunk(s), 15.5s, 0.25 MB)
```

Checks: decode, duration ≥ 0.3 s, loudness within −35…−8 LUFS (warn outside
−22…−12), true peak ≤ −0.1 dBFS, and silence limits. `QA: FAIL` exits with code
5 and must be fixed before delivery. `--no-verify` exists but is discouraged.

## Requirements

- `python3` 3.9+ (standard library only).
- `ffmpeg` + `ffprobe` for stitching dialogue, merging long text, SRT timing,
  and QA. Without ffmpeg, use `--no-stitch` and skip verification.
- Network access to `speakee.tnxbd.top` (no API key needed).

## Exit codes

| Code | Meaning |
|---|---|
| 0 | success |
| 1 | generic error |
| 2 | usage error |
| 3 | validation (language/model/voice/preset/text) |
| 4 | network or API error |
| 5 | audio QA failed |

## Privacy, safety & limitations

- **Text leaves the machine.** Synthesis requests go to `speakee.tnxbd.top`.
  Do not send passwords, API keys, private documents, or personal data without
  the user's consent.
- **Responsible use.** Only clone a voice with the speaker's permission. Do not
  use this skill for impersonation, fraud, or deception. Follow local law.
- **No SLA.** The API is a free community service. Keep `--workers` modest,
  leave caching on, and expect occasional 429/5xx responses.
- **Demo audio** is generated output; voice and model rights belong to their
  owners.
- **Platforms.** Tested on Linux (Termux/Android) with Python 3.14; CI covers
  Python 3.9/3.11/3.13. The Python CLI works on macOS and Windows; the `.sh`
  helper scripts need a POSIX shell (Git Bash or WSL on Windows).
- **ffmpeg** is optional but required for stitching, SRT timing, and QA.

## FAQ

**Is it free?** Yes. The TNxBD Studio (Speakee) API is public; the skill is MIT.

**Does it need an API key?** No.

**Can it do multiple speakers?** Yes — `conversation` with `--map` or automatic
voice assignment, parallel synthesis, one stitched file. Lines with no
`Speaker:` prefix are the narrator/commenter and use a **3rd** voice via the
special `narrator` key. If two speakers share a voice, the script prints a
`WARNING` — map each speaker to a different voice.

**What about long articles?** Automatic chunking at sentence boundaries with
per-chunk caching and merging.

**Can I use my cloned voice?** Yes — `uid` mode with the voice UUID.

**Which model should I use?** `sonic-3.5` (default) for quality; `sonic-turbo`
for speed.

**Can it transcribe audio?** Yes — `stt`, `transcribe`, and `subtitle` turn an
audio/video file into text, word timestamps, and SRT/WebVTT subtitles. Long
recordings are split into ~120 s chunks automatically.

**Do I need to pass the language for STT?** No, but auto-detection can be
unreliable on short clips. Pass `-l <code>` (e.g. `-l bn`) when you know it.
